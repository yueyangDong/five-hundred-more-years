# v11 · 按钮「墨涡」交互方案

> 需求原文：为按钮设计点击与悬停等交互时的动画效果，呈现类似黑洞漩涡的视觉表现 —— 以按钮中心为漩涡核心，
> 产生向内螺旋吸附并伴随扩散涟漪的层次感，包含粒子或光晕被吸入的动态轨迹、速度渐变的旋转扭曲，
> 以及点击瞬间向外扩散的涟漪波纹；确保动画触发时机、持续时长与缓动节奏自然流畅，过渡衔接平滑不突兀，
> 并适配不同按钮尺寸与深色/浅色主题。
>
> 第二版修订：**点击之后出现漩涡吸进去的那种，其他的按钮交互不变。**

实现位置：`index.html` 的 `<style id="vxcss">`、`<canvas id="vx">`、`initVxVortex()`（在 `init()` 里调用）。
整层**不碰任何游戏逻辑**，也不改任何按钮既有样式 —— 平衡回归已验证零污染。

---

## 0. 两档强度，不是一套力度

第一版对 hover 与 click 用了同一副力度：鼠标一移上去就持续旋转吸附、click 再向外爆三道涟漪。
实测下来两个问题：悬停太吵（高频动作，每次划过都在动）；而「点击」读起来是**炸开**而不是**吸进去**。

第二版把方向和力度一起拆开：

| 档 | 触发 | 画面 | 为什么 |
|---|---|---|---|
| **悬停** | `pointerover`（仅精细指针） | 只留**一圈微光**：一团柔和光晕 + 一段缓慢转动的亮弧 + 核里一颗小光点。**整团光收在按钮框内，不外溢一个像素** | 悬停是高频、无目的的动作，分寸要压到「感觉得到它在转，但说不出在动什么」 |
| **按下** | `pointerdown` | 整个结构展开：五层涡体 + 粒子 6.5 倍速内吸被吞 + **按钮的壳被卷进核里** + 按钮本体塌缩变暗 | 一次一次、有明确意图，值得给一整下 |

向外扩散**退成抬手之后的一道尾声**。理由：「炸开」和「被吸进去」是相反的读法，不能同时当主角。
第一版让外爆先发生，于是「点击」的语义就变成了炸开 —— 这是被打回重做的直接原因。

**一个细节**：`pointerdown` 才是这一下的起点，click 太晚了（要等抬手，通常 80–200ms 之后）。
所以吸收挂在 `pointerdown`，click 只负责收尾发那道涟漪。

## 1. 为什么必须走独立画布

一上手想的是给 `.opt` 加伪元素或子元素，三处都堵死了：

| 障碍 | 具体 |
|---|---|
| 伪元素已被占用 | `.opt::before` 是左侧金线，`.opt::after` 是底部暖光；Apple 主题里还有 `.opt::before,.opt::after{display:none}`。要加就得改主题规则，跨主题一致性破功 |
| 会被裁 | `.opt{overflow:hidden}` —— 向外扩散的涟漪、飞散的粒子全部裁掉 |
| **动画播不完** | 选项按钮在 `click` 的**同一个 tick** 里被 `renderLife()` 整块重建。挂在按钮上的动画最长只能播到「点击那一帧」 |

第三条是决定性的。独立画布之后，「按钮被销毁」反而成了效果的一部分 —— 涟漪与残余涡体在按钮消失后
继续播，读起来正是「它被吸进去了」。

代价：画布读不到按钮的 DOM 样式（背景色、边框、圆角）。所以配色按主题分两套，
并且**不引 `mix-blend-mode`**（那会让整页多一次全屏混合）：

| 主题 | 逻辑 | 表现 |
|---|---|---|
| 浅色 | 在绢本上画**墨涡**，靠「暗」说话 | 暗墨 + 赭金 + 一点朱砂，`source-over` 压暗 |
| 深色 | 在夜空里画**吸积盘**，靠「亮」说话 | 亮金 + 朱砂，`source-over` 提亮 |

## 2. 按下时展开的五层结构

从下到上，缺一层都不像黑洞：

1. **远场引力雾**（半径 `2.7R`）—— 让涡与纸面之间没有硬边。少了它，涡像贴在按钮上的一块贴纸。
2. **内盘热辉**（`.42R ~ 1.25R`）—— 「这里很烫」的底子，暖金径向渐变。
3. **旋臂**（`.86R ~ 2.1R`）—— 三条真螺旋，见第 4 节。
4. **洞心**（`.46R`）—— 把中心真正压黑。**「黑洞」的全部说服力都在这颗黑点上**，
   半径压到 `.46R`（558px 按钮上约 9px）是为了不糊住按钮文字 —— 它只需要够小够黑。
5. **光子环**（`.52R` 亮边 + `.63R` 暗边）—— 「光在洞口拐了个弯」的那一圈。

> 浅色主题下光子环为什么能「亮」？因为它底下已经铺过远场雾与旋臂。
> **亮不是一个绝对值，是相对于周边而言的** —— 这层顺序错了，浅色版就会失效。

这五层只在**吸收态**（`V.arousal > .10`）绘制。`arousal` 由 `pointerdown` 拉满、按 τ=.42 衰减，
刚好覆盖「按下 → 被吞 → 抬手一道尾声」这一整段（约 1s）。超过这个窗口就回落成悬停的微光。

## 3. 按钮的两种被碰方式（都不是内联样式）

「被吸进去」有两条线索落在按钮自己身上，但**一条内联样式都没写**。

### 3.1 壳被卷进核里（画布画，不碰 DOM）

画布搬不进按钮里的 DOM 内容，但**壳**的收缩扭曲足以让眼睛读出「这个按钮被吸进去了」：

```js
e  = u ^ 0.68              // 前段快、后段慢 —— 吞进去的手感
k  = 1 - 0.82 e            // 1 → .18，一路缩进核里
rot= dir × 2.9 e           // 边收边转，才像「被卷」
scale(k, k × (1 - .16 e))  // 竖向多收一点，像被吸瘪
lineWidth = 1.9 / k        // 除以 k → 视觉上等宽，不跟着一起缩
```

圆角矩形按按钮 `rect` 现算（`rad = min(11, h × .24)`），所以 558×53 的选项行、206×39 的侧栏项、
方形图标按钮共用同一套，无需分支。内层再叠一个 `.70` 倍的更淡轮廓 —— 壳在塌的层次。

生命周期 `.46s`，用 `V.shell` 存一份**坐标快照**（不跟随元素）：按钮被重建后它仍在原地收完。

### 3.2 按钮本体塌缩变暗（一条类规则）

「变暗」用一条 `#vx` 里的规则 + 一个瞬时挂上/摘掉的类：

```css
.vx-suck{filter:brightness(.52) saturate(.70)!important}
```

而「塌缩」**不在这里做** —— 由按钮原有的 `.pressed{transform:scale(.97);transition:transform 100ms}`
负责（游戏自己在 `pointerdown` 加这个类）。这一层只补「变暗」一件事，`transform` 一下都不碰，
所以两者是**叠加**而非顶替：按下时元素的 `class` 实测是 `opt pressed vx-suck`，
`computed transform` 是 `.pressed` 自己的 `matrix(0.985…)`（100ms 过渡还在走）。

为什么非得用类 + `!important`，见第 9 节 —— 这里连着踩了三个坑。

## 4. 「速度渐变的旋转扭曲」怎么画出来

不是调参调出来的，是两个物理关系直接画出来的：

**粒子**
- 角速度 `ω = spin × 3.77R / (0.30R + r)` —— 即 `ω ∝ 1/r`，越靠近核心转得越快；
- 径向 `v_r = -R × mul × (0.75 + 3.2R/max(r,0.3R) + 0.05r/R)` —— 近核处 `1/r` 项主导，越吸越快。

两条叠起来的效果：粒子在外圈几乎水平平移，进入核心区突然甩成一道弧，最后被吞。
被吞时并进核心亮度（`V.eat`），所以你会看到中心「闪一下」——像真的咽下了一口。

**旋臂**
用半径随角度增长的**真螺旋**（`r = R(0.86 + u × 1.22)`），不是同心圆弧。
缠绕度还随呼吸缓慢收放（`wind = 1.15 + 0.42 × sin(now × 0.13)`），
所以看着是「越缠越紧、又被甩开」。三条臂的缠绕度、长度、明暗各不相同 —— 完全一致会一眼看出是复制粘贴。

> 第一版用的是「26 段短弧 × 4 个半径环」，结果是一圈圈同心圆，像**咖啡杯底的茶渍**。
> 这是被打回重做的直接原因。

**悬停的微光**为什么不照搬这一套：微光那团环用的是**径向渐变给柔边**，而不是描一条线。
描边会读成「贴了个椭圆环」，柔边才读成「一团光在转」。浅色主题下尤其明显 ——
浅底上靠线是立不住的，只能靠「一团比周围稍暗的晕」。

## 5. 节奏表

所有时间推移（除涟漪）都用**指数逼近**而不是 keyframe：
`V.charge += (want - charge) × (1 - e^(-dt/τ))`。
理由：指数逼近在任何时刻都连续，**中途反向也不会跳变** —— 而 keyframe 动画在从「起旋 40%」切成
「消散」时会出现可见的一跳。这一点在鼠标快速划过一排按钮时会被放大。

| 事件 | 时长 | 缓动 | 说明 |
|---|---|---|---|
| hover 微光起 | 240ms | 指数逼近 τ=.075 | 快起、自然落定 |
| 微光亮弧转速 | 常数 `spin × .62` | —— | 比吸收态慢一半，只做「它在动」的提示 |
| **按下内塌** | 收敛 τ=.085 | 指数逼近 | 核心收缩 26%、亮度 ×1.9；22 颗粒子以 **6.5 倍**速度被吞（18 小 + 4 大） |
| **按下纳光** | 580ms 光斑 | `1-(1-u)^2` 先慢后快 | 核心「纳进来」的那口光，半径 `3.8R` |
| 壳被卷入 | 460ms | `u^0.68` 前快后慢 | 半径一路缩到 `.18`，同时转 2.9 rad |
| 按钮变暗 | 瞬时（类挂上） | —— | 见第 9 节：这里是**故意**不给过渡的 |
| **抬手尾声涟漪** | 900ms | `1-(1-u)^2.6`，延迟 120ms | 只此**一道**（第一版是三道错峰），半径 `Rout × .92` |
| 抬手金箔 | 420–780ms | 阻力 `e^(-t/.16)` | 9 片，向外飞散并翻滚 |
| 离开散尽 | 320ms | 指数逼近 τ=.13 | 比起旋慢 —— 散得比聚得慢一点才像有惯性 |

**涟漪从哪出发**：从**按钮中心**（与「以按钮中心为漩涡核心」一致），而不是落点。
落点另给一份很轻的反馈（一小团柔光 + 9 片金箔），这样既不破坏漩涡的向心性，又不丢「我按的是这里」。

## 6. 适配：一套参数吃下所有尺寸

全部从 `getBoundingClientRect()` **每帧现算**（所以按钮 hover 上浮 1px、页面滚动、窗口改尺寸都跟得上）：

| 量 | 公式 | 意图 |
|---|---|---|
| 核心半径 `R` | `clamp(hh × .80, 14, 42)` | 跟**高度**走 —— 漩涡是个盘，高度是它的直径 |
| 横向拉伸 `sx` | `clamp(w / (h × 3.4), 1, 2.2)` | 跟**宽高比**走；方形按钮自然得到 1，宽按钮得到「躺着的盘」 |
| 涟漪上限 `Rout` | `clamp(hh × 3.0, 72, 168)` | 跟高度走，再夹住上下限 |
| 盘面俯仰 `ASP` | 常量 `.84` | 盘「躺下来」才有体积感 |
| 悬停微光直径 | `R × 2.2`（再乘 `ASP`） | **刻意收在按钮高度之内**，这是「不外溢」的来源 |

实测覆盖：**558×53** 的选项行、**206×39** 的侧栏项、方形图标按钮，用同一套参数，无需按尺寸分支。
断言口径：按钮框外 14px 的环带上，悬停时为 **0 像素**（浅色偶尔 29 像素，是渐变环边缘不到 1px 的溢出）。

## 7. 让衔接不突兀的四件事

1. **`relatedTarget` 归属判断**。`pointerout` 在光标移到按钮内部的 `<span class="eff">` 上时也会触发。
   不判断就会「离开 → 重进」，涡会抖。
2. **按下后拖出按钮不算数**。`pointerout` 里只在 `e.buttons` 为真时才清 `V.pressed`
   （按住拖出 = 这一回不算；手指抬起后浏览器也会补一次 `pointerout`，那一次不能清）。
3. **续涡**。事件翻页后 DOM 整块换新，而光标往往没动 —— 光靠 `pointerover` 就再也起不来了。
   引擎在按钮失连后会探测光标下有没有新按钮并接上去：
   - `rebindDelay = +555ms`：躲开按下自身的塌陷，让它先播完；
   - `keepAwake = +1.5s`：空闲时 rAF 会停，得把引擎多留一会儿才有探测窗口。
   实测「整块重渲染 +1.3s 后，光标处覆盖 4424 像素 ✓」；光标下若落的不是按钮，则不续涡（正确行为）。
4. **点击不拖慢逻辑**。`pointerdown` 与 `click` 都挂在 document 的**捕获阶段**，
   先记下坐标触发动画，游戏自己的 `onclick` 照常同步执行 —— 没有任何人为延迟，也没有双击风险。

## 8. 降级与开销

| 场景 | 行为 |
|---|---|
| 粗指针（手机 / 触屏） | 不做悬停微光（`matchMedia('(hover:hover) and (pointer:fine)')` 判定），但**按下吸收照常** —— 那本来就该点哪儿响哪儿 |
| `prefers-reduced-motion` | 悬停覆盖 0 像素、完全不起旋；按下只给一帧柔光（**不是**彻底没有反馈） |
| 高 DPI | `devicePixelRatio ≤ 1.5` 封顶 |
| 空闲 | `idle()` 成立即停 rAF，不留空转 |

**实测开销 ≈ 0**。`_vx.js` 同口径测「静止 24.4 fps → 微光在转 23.9 fps」，掉幅 **0.5**
（基线 24fps 本身是无头 Chromium 软件渲染的结果，不是游戏的开销）。
另外这个探针验过：静止时画布 alpha 覆盖 **0 像素**、移开后 **1.8s 归零**，
即这层不转的时候不占任何像素。

## 9. 按钮本体：连着的三个坑（这一节是本轮最贵的）

「按下把按钮压暗」看着是一行代码的事，实际连着踩了三次，一次比一次深：

**坑 1 — 写内联 `transform` 会顶掉游戏自己的按下反馈。**
游戏在 `pointerdown` 给按钮加 `.pressed`，规则是 `.pressed{transform:scale(.97);transition:transform 100ms}`。
我写 `el.style.transform = 'scale(.935)'` 之后，`.pressed` 的 `transform` 被内联压过
（内联优先于类），于是「原有按下反馈」被替换而不是叠加 —— 直接违背「其他按钮交互不变」。

**坑 2 — 写内联 `filter` 会被逐帧冲掉。**
游戏有一套弹簧动画系统（`v4SpringTo`），它的 `v4Paint()` **每帧重写**：
`el.style.opacity` / `el.style.transform` / `el.style.filter`。
`.opt` 的点击回弹正是这条链（`v4Stop → v4State.set(scale:.97) → v4SpringTo(scale:1)`）。
所以内联 `filter` 会被它每帧冲成 `none`，「变暗」根本留不住。

**坑 3 — 给内联配 `transition` 也没用。**
因为它每帧都在重写值，过渡压根推进不了：按下 90ms 后读 `getComputedStyle` 还是 `brightness(1)`，
看起来像「过渡刚起步」。这一条最误导 —— 会让人以为「再加长一点时长就好了」。

**解法**：一条 `!important` 的类规则压过逐帧内联，`transform` 一概不碰（塌缩交给 `.pressed`），
类一摘掉按钮 100% 回到原样。

```
按下： el.classList.add('vx-suck')     → class = "opt pressed vx-suck"
      computed: brightness(.52) saturate(.7)  |  matrix(.985…)  ← 后者是 .pressed 的
抬起： el.classList.remove('vx-suck')  → class = "opt picked"，内联里没有这一层的任何东西
```

> 顺带记一个更早的同类 bug：`<style id="vx">` 与 `<canvas id="vx">` **id 撞了**，
> `getElementById` 返回 head 里的 `<style>`，`!cv.getContext` 判定为真 → **整个漩涡层静默地从未初始化**。
> 表现是「代码全对，画面什么都没有」。视觉层整层不生效时，先查 id 冲突。
>
> 这两条共同的教训：**视觉层「什么都没发生」时，不要读代码找逻辑错，要去量真实值** ——
> 探针第一次跑就把这两个都抓出来了。

## 10. 调参入口

都在 `initVxVortex()` 顶部，改完刷新即可：

| 想改什么 | 改哪里 |
|---|---|
| 配色 / 整体浓淡 | `PAL.dark` / `PAL.light`：`hazeA` 外场雾、`hotA` 内盘热辉、`voidA` 洞心、`armSoft` 旋臂软底、`edgeA` 光子环 |
| 悬停微光的浓淡 | `drawHalo()` 里的 `.40 / .34`（中心柔光）、`A × .58`（亮弧）、`R × 2.2`（直径，调大就会外溢） |
| 微光转多快 | `drawHalo()` 里的 `V.spin × .62` |
| 大小 | `geom()` 里的 `R` / `sx` / `Rout` 三个 clamp |
| 吸得多快 | `stepPart()` 的径向式；`3.2` 越大近核加速越猛，`.05` 越大外圈越不磨蹭 |
| 转得多快 | `stepPart()` 的 `3.77`（角速度系数）；`V.spinV` 的目标值 `2.9` 是基础角速度 |
| 按钮压多暗 | `#vxcss` 里的 `.vx-suck{filter:brightness(.52)}` |
| 塌缩多深 | 那是 `.pressed` 的事（游戏原有，`scale(.97)`），这一层不参与 |
| 壳收得多快 / 转多少 | `drawShell()` 里的 `ttl:.46`、`2.9`、`1 - .82e` |
| 按下吸入力度 | `press()` 里的粒子数 18+4、`V.impl 1.15`、`V.eat 1.35` |
| 尾声涟漪 | `tap()` 里的 `Rout × .92`、`delay:.12`、`dur:.90` |
| 吸收态窗口多长 | `draw()` 里的 `V.arousal = decay(..., .42)` |
| 起落快慢 | `draw()` 里指数逼近的两个 τ（`.075` 起 / `.13` 落） |

| 断言 | 通过标准 |
|---|---|
| `静止` | 画布 alpha 覆盖 **0 像素**（这层不常驻） |
| `hover +140ms / +2.2s` | 有一团光；且 **按钮框外 14px 环带 = 0 像素**（微光不外溢，这是「只留一圈微光」的硬断言） |
| `按下 +90ms` | 核心均值显著高于悬停；**框外环带 > 3000 像素**（粒子从框外被吸进来）；`class` 含 `vx-suck`；`computed filter` 含 `brightness(0.52)`；`transform` 不等于 `matrix(1,…)`（原有 `.pressed` 在走） |
| `抬起 +160ms` | `class` 不含 `vx-suck`；内联里没有这一层留下的 `filter/transform`（其他交互不受影响） |
| `点击 +80/160/320/1120` | 外扩覆盖先涨，**+1120ms 归零**（尾声涟漪一道、且收干净） |
| `重渲染 +1.3s` | 光标处覆盖 > 0（续涡）；光标下不是按钮时不续涡 |
| `移开 +1.8s` | **0 像素** |
| `小按钮 206×39` | 框外同样 0 像素（证明一套参数吃下所有尺寸） |
| `mobile` | 无悬停微光；轻触有吸收 |
| `reduced-motion` | 悬停 0 像素；按下只有一帧柔光 |
| `帧率` | 与基线的掉幅 |
| 另存放大的画布单图 | `vx-<theme>-zoom.png`（悬停）、`vx-<theme>-press-zoom.png`（按下）、`vx-<theme>-ripple-zoom.png`（尾声）、`vx-<theme>-press.png`（真实页面按下）—— 供肉眼判美术 |
