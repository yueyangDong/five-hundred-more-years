# 事件动画：开源方案调研与引入指南

> 本文回答三件事：**GitHub 上有什么能用**、**哪些不能用（许可证）**、**怎么接进来并推上线**。
> 所有体积数字都是**实测**（`_libsize.js` 直接下载 CDN 构建产物后量原始 / gzip），不是文档里抄的。

---

## 一、先说结论

1. **引擎层不需要引入任何库。** 项目已有的手写动效层（v4 Spring 缓动 + v9 水墨/祥云/落印）覆盖了九成场景，且完全可控、零体积。引入 anime.js / Motion 这类通用补间库属于**能力重复**。
2. **唯一值得引入的是粒子系统。** 粒子物理（重力、空气阻力、横向摇曳、纸片自转）手写要两三百行且调试成本高，而 `canvas-confetti` 用 **4.3 KB gzip** 就把它做完了。已接入，用于结局揭晓。
3. **LottieFiles 上的免费动画不能用。** 它的 "Lottie Simple License" 含**传染条款**，与本项目的 MIT 授权冲突。这条是本轮调研最重要的发现，详见第三节。

## 二、候选库实测

| 库 | 版本 | 许可证 | 原始 | **gzip** | 结论 |
|---|---|---|---|---|---|
| [canvas-confetti](https://github.com/catdad/canvas-confetti) | 1.9.4 | **ISC** | 10.6 KB | **4.3 KB** | ✅ **已接入** |
| [lottie-web](https://github.com/airbnb/lottie-web)（light，SVG 渲染器） | 5.13.0 | **MIT** | 164.4 KB | 45.5 KB | ⚠️ 引擎可用，素材是成本 |
| lottie-web（full） | 5.13.0 | **MIT** | 298.5 KB | 74.5 KB | ⚠️ 同上，多表达式求值 |
| [anime.js](https://github.com/juliangarnier/anime)（UMD） | 4.5.0 | **MIT** | 115.3 KB | 39.7 KB | ❌ 与已有 v4 Spring 层重复 |
| [tsParticles](https://github.com/tsparticles/tsparticles)（slim） | 3.x | **MIT** | 149.1 KB | 41.2 KB | △ 只在要"持续粒子场"时才值 |
| [Motion](https://github.com/motiondivision/motion)（Motion One） | 12.x | **MIT** | 136.6 KB | 45.4 KB | ❌ 同上，重复 |

> 实测脚本：`node _libsize.js`（仓库里，`.gitignore` 已忽略 `_*.js`）。
> anime.js v4 虽然 README 主推 ESM，但 npm 包**保留了 UMD 构建** `dist/bundles/anime.umd.min.js`，可直接 `<script>` 引入——这一点文档里没写清，容易误判为"必须走构建"。

### 逐个说清楚"值不值"

- **canvas-confetti** —— 值。它只做一件事（纸片/粒子迸发），做得干净，无依赖，`pointer-events:none` 不挡交互。对"结局那一刻要有分量"这个需求，是最短路径。
- **lottie-web** —— 引擎本身 MIT、无风险，但 **Lottie 的价值在动画数据，不在引擎**。一个像样的中国风动画 JSON 通常 30–200 KB，而且要么买、要么自己做（After Effects + Bodymovin 导出）。对单人项目，性价比不如手写 SVG/CSS。
- **anime.js / Motion** —— 都是好的补间库，但本项目已经有 `v4SpringTo` / `v4Stop` 这套 Apple 风格弹簧动效层，再叠一层补间引擎只会让"动效从哪来"变得难追溯。
- **tsParticles** —— 功能最强（星空、落雪、雾），但项目已有 `#bgFx` canvas 背景层。**只有当你想要"漫天飞雪 / 落樱 / 流萤"这类持续粒子场**时，才值得为它付 41 KB。

## 三、许可证红线（重要）

### LottieFiles 的免费动画**不能直接用于本项目**

LottieFiles 上标着"免费"的动画，适用的是 **Lottie Simple License**。原文关键句：

> *"…provided that any display, publication, performance, or distribution of Files must contain (and be subject to) the same terms and conditions of this license. Modifications to Files are deemed derivative works and must also be expressly distributed under the same terms and conditions of this license."*

这是**著作权左（copyleft）**条款：动画文件的衍生作品必须以**相同条款**分发。

| | 本项目 | Lottie Simple License |
|---|---|---|
| 允许闭源再分发 | ✅ | — |
| 允许附加不同条款 | ✅ | ❌ 明令禁止 |
| 传染性 | ❌ 无 | ✅ 有 |

**结论**：二者不能共存。把 LottieFiles 的免费动画放进本项目，会让"本作品以 MIT 发布"这个声明变得站不住脚，除非整个作品改以 Lottie Simple License 发布——而那个许可证**不是 OSI 认证的开源许可证**，会连带影响项目的开源身份。

### 那 Lottie 这条路还能走吗？能，但素材必须换源

| 素材来源 | 许可证 | 可用于 MIT 项目 |
|---|---|---|
| LottieFiles 免费区 | Lottie Simple License | ❌ 有传染条款 |
| LottieFiles 付费区 | 视具体授权 | △ 需逐项确认，多数为"可用于商业项目"但仍非开放许可 |
| **自己用 AE + Bodymovin 导出** | 你的版权 | ✅ **推荐** |
| CC0 / MIT 的 Lottie 集合（需逐个核实） | CC0 / MIT | ✅ |

### 其余候选库的许可证都安全

MIT / ISC 都是宽松许可，只要求在再分发时保留版权声明与许可原文。**本项目已经满足**：内联的 confetti 代码块顶部保留了版本、许可证与来源注释。

## 四、引入路径：三选一

| 路径 | 做法 | 优点 | 缺点 | 本项目 |
|---|---|---|---|---|
| **A. CDN 外链** | `<script src="https://cdn.jsdelivr.net/npm/…">` | 不占体积、更新方便 | **破坏"离线可用"**；多一次网络往返；CDN 挂了就没了 | ❌ |
| **B. 内联进单文件** | 把构建产物贴进 `<script>` | 保持单文件、双击即玩、离线可用 | 体积增大；升级要手动替换 | ✅ **采用** |
| **C. 走构建** | npm + bundler | 依赖管理规范 | **破坏"零构建"**，与项目定位冲突 | ❌ |

### 为什么选 B

项目的第一约束是「**单文件 / 双击即玩 / 离线可用**」——它写在 README 的"快速开始"里，是给玩家的承诺，不是实现细节。A 和 C 都会破坏它。

内联的代价是**可量化且透明**的：

```
接入前  index.html   536.1 KB 原始  /  178.3 KB gzip
接入后  index.html   547.3 KB 原始  /  182.5 KB gzip
                      +11.2 KB (+2.1%)  /  +4.2 KB (+2.3%)
```

**2% 的体积，换结局揭晓那一刻的金箔**——这笔账划算。

## 五、已落地的示范：结局金箔粒子

### 接入位置

1. **库本体**：`index.html` 中主逻辑 `<script>` 之前，一个独立 `<script>` 块，顶部注释标明版本 / 许可证 / 来源 / 移除方法。
2. **包装函数**：`gcBurst(name)`，定义在 v9 国潮动效区（`fxInk` / `fxInkDot` 之后）。
3. **调用点**：`renderSettle()` 内，押后 260ms —— 先让结局称号的逐字揭示走完，粒子再扬起来，否则两者互相抢戏。

### 分级策略

金箔的分量来自**它不常出现**。所以只给值得的结局放：

```js
const GC_BURST_TOP = ['打破命簿','白日飞升','肉身菩萨'];            // 三发（含天女散花）
const GC_BURST_MID = ['名垂青史','德被苍生','隐居悟道','一代名臣','富可敌国','封侯拜将',
                      '一代名医','权倾朝野','富甲一方','大限圆满','一代高僧','得道真人','江湖散人']; // 两角斜射
// 其余一律不放：平凡一生 / 业火焚身 / 孤苦终老 / 早逝天才 / 青灯古佛 / 马革裹尸
```

### 配色沿用 v9 国潮色盘

```js
const GC_GILT = ['#c9a227','#f2d589','#bd3a2b','#d96a5a','#35688f','#f4efe4'];
//                鎏金     浅金      朱砂     浅朱      青金      绢本素白
```

不放彩纸那种高饱和色——那是西式庆典的语汇，跟水墨绢本不搭。

### 怎么摘掉它

三步，无其他耦合：

1. 删掉内联 confetti 的那个 `<script>` 块；
2. 删掉 `gcBurst` 函数与三个 `GC_*` 常量；
3. 删掉 `renderSettle()` 里那一行 `setTimeout(()=>gcBurst(G.ending.name), 260)`。

删完体积立刻回到 536 KB。

## 六、如果将来要做更复杂的叙事动画

比如「卷轴展开」「水墨花开」「云海翻涌」这类**有分镜的矢量动画**，两条路：

### 路一：手写 SVG + CSS（推荐先试这个）

项目已经在用这条路：祥云用 `mask-image` + data-URI，远山用三层路径，法阵用 SVG。**增量成本低，完全可控，零体积。**

适合：几何化、程式化的图形（纹样、印鉴、云气、光晕）。

### 路二：引入 lottie-web + 自制素材

只在**真的需要 AE 级动画**时才走：

1. 用 After Effects 制作动画（或从零画矢量）；
2. 装 [Bodymovin](https://aescripts.com/bodymovin/) 插件导出 JSON；
3. 用 [lottie-web](https://github.com/airbnb/lottie-web) 的 **light 构建**（45.5 KB gzip）内联渲染；
4. 动画 JSON **一并内联**（避免额外请求），或用 `animationData` 直接传对象。

> ⚠️ 再次提醒：**不要**从 LottieFiles 下载 JSON 塞进本项目，除非你愿意接受第三节说的许可证传染。

## 七、推送到 GitHub

### 提交

```bash
cd "D:/我的前世今生-三生三世/还想再活五百年"

# 看一眼将要提交什么（_*.js 和 _shots/ 已被 .gitignore 忽略）
git status --short

git add index.html README.md docs/
git commit -m "feat(career): 职业路线 + v9 国潮视觉层 + 结局金箔粒子

- 新增四职业路线（仕途/商道/行伍/医道），21 条专属事件 + 5 条专属结局
- 职业事件数值按「每选项净贡献」对齐老池，5 条职业结局实测落在 1.3%–2.6%
- v9 国潮视觉层：水墨五色、祥云暗纹、远山剪影、鎏金标题、朱砂印章
- 新增水墨晕开 / 落墨点两处国潮动效
- 内联 canvas-confetti v1.9.4（ISC）做结局金箔，+4.2 KB gzip
- 修复：结局判定视图 gg 漏传 career 字段，导致 5 条职业结局恒不可达"

git push origin main
```

### 验证线上生效

```bash
# 1. 看 Actions 是否跑完（Pages 通常 30–90 秒）
#    仓库 → Actions 标签页，或直接访问：
#    https://github.com/yueyangDong/five-hundred-more-years/actions

# 2. 等构建完成后，验证线上文件确实是新版（比对比本地与线上的 gzip 后长度）
curl -s -H "Accept-Encoding: gzip" -o /tmp/live.gz -w "%{size_download}\n" \
  https://yueyangdong.github.io/five-hundred-more-years/

# 3. 或者加一个 cache-busting 参数硬刷新看一眼
#    https://yueyangdong.github.io/five-hundred-more-years/?v=career
```

### 如果线上没更新

按顺序排查：

1. **Actions 是不是失败了** —— 看 run 日志，最常见是依赖或权限问题；
2. **是不是 CDN 缓存** —— Pages 的 CDN 有几分钟边缘缓存，硬刷新（Ctrl/Cmd+Shift+R）或加 `?v=2`；
3. **分支/目录设置对不对** —— Settings → Pages 应指向 `main` 分支根目录；
4. **是不是 push 到了别的分支** —— `git branch --show-current` 确认。
