# v10 国潮视觉增强与配图方案：开源调研 · 技术选型 · 落地记录

> 本轮任务（2026-09-27）有四件事与视觉相关：**① 事件默认全部展开**、**② 背景祥云等装饰加浓**、
> **③ 去 GitHub 找当前最新最热的可行方案并参考已有项目**、**④ 给事件配图（含调研是否存在可用的生图 skill）**。
> 本文记录这四件事的调研结论与落地细节，供后续迭代与复核。

---

## 一、先给结论

| 问题 | 结论 |
|---|---|
| GitHub 上有没有「许可干净 + 可内联」的中式矢量纹样库？ | **没有。** 唯一规模化的中国纹样开源项目是 NC（非商业）许可，且只出 PNG 卡片、无矢量稿 |
| 那祥云/远山/云头怎么办？ | **全部自绘 SVG path**（约 0.5 KB/组），以 `mask-image` 平铺、`filter` 做墨晕 |
| 有没有值得引入的现成代码？ | 只有**技术手法**值得抄，**没有整库值得引**（见 §二） |
| 纸纹/宣纸质感要不要用位图？ | **不要。** 用 `feTurbulence` 现场生成，比内联纸纹位图省 2–3 个数量级体积 |
| 有没有可用的生图 skill？ | **有。** 内置 `ImageGen`（文生图 / 图生图），本轮据此产出 9 张配图 |
| 配图怎么进单文件而不炸体积？ | 16:7 横幅 → 540px 宽 → 自适应质量 WebP → base64 内联，**9 张共 160 KB（占单文件 19.5%）** |

## 二、GitHub 调研：为什么最后选择「自己画」

调研目的是找**可直接内联、无需构建、许可允许商用**的中式装饰素材或组件。逐个说清楚。

### 2.1 中国传统纹样图鉴（Wényàng）—— 不可用

- 仓库：`dososo/chinese-traditional-patterns`
- **双许可**：
  - 代码与数据结构（脚本、JSON/CSV 结构）：**MIT**，可自由商用；
  - **纹样图像与文字内容（PNG 卡片图、详情文案）：CC BY-NC 4.0** —— 仅可非商业使用，需署名，**禁止未授权商用**。
- 另一点同样致命：项目**目前只提供 PNG 卡片图（1086×…）**，官方路线图里「新增 SVG 描边稿、配色色卡文件」仍属**未来规划**。
- **判定：禁用。** 图像部分 NC 与商用冲突；且没有矢量稿，位图纹样内联进单文件体积不可接受。

> 这是本轮最重要的一条排雷：它看起来是「开放、免费的中国传统纹样图录」，很适合做国潮装饰，
> 但**看图不等于能商用**，双许可里真正有用的那一半（图）恰好是受限的那一半。

### 2.2 {Shan, Shui}* —— 许可干净，但不适合直接引

- 仓库：`LingDong-/shan-shui-inf`（约 5.6k stars）
- **MIT 许可**，纯 JS 程序化生成**无限横向长卷**的 SVG 山水（Perlin 噪声 + 数学函数建模山与树）。
- 为什么不引：
  1. 它是**横向无限长卷**，本项目的场景图是**单屏 16:7 横幅**，形态不匹配；
  2. 它是「生成一整张画」而不是「提供一组可复用的装饰母题」，接进来等于换掉整套背景逻辑；
  3. 单文件零依赖是硬约束，引入等于多一份几百 KB 的生成器。
- **实际借用的是「思路」而非代码**：远山用**多层噪声剪影 + 分档浓淡**来造纵深。本项目的 `gc-scape`
  正是这一手法的极简实现（三档远/中/近山 + 一层雾带，全部手写 path）。

### 2.3 其他扫过但未采用的类型

| 方向 | 为什么不采用 |
|---|---|
| 中式 UI 组件库（如水墨风组件库） | 需构建、体积以 MB 计，与本项目「零依赖零构建」冲突 |
| 内联纸纹/宣纸位图 | 一份纸纹动辄 1–3 MB；`feTurbulence` 现场生成可省 2–3 个数量级 |
| 现成祥云/回纹 SVG 图标集 | 许可多为不明或 CC-BY-NC；且风格与本项目调性不统一，改起来比自己画贵 |
| 手写毛笔字库 | 唯一**有真实体积代价**的选项（单个中文字库子集化后仍有几十到上百 KB），本轮不做 |

### 2.4 最终采用的技术手法（全部零依赖、可内联）

| 手法 | 用途 | 体积代价 |
|---|---|---|
| `@property --gcSheen` 注册 `<angle>` | 金线流光（conic-gradient 起点角可插值） | ~0.3 KB |
| SVG `feTurbulence`（fractalNoise） | 宣纸纤维颗粒，替代纸纹位图 | ~0.4 KB |
| SVG `feDisplacementMap` | 墨边晕开（贴在远/中景山体上） | ~0.4 KB |
| CSS `mask-image` + 内联 SVG data-URI | 祥云暗纹 / 云海雾带的平铺与横移 | ~1.2 KB（含自绘 path） |
| 手绘 `<path>` 母题 + `<use>` 缩放阵列 | 祥云大周期平铺块、如意云头角花 | ~0.5 KB/组 |
| `mix-blend-mode`（multiply / screen + invert） | 深浅两套主题下同一份素材各自成立 | 0 |

> **一句话**：本轮视觉层的全部新增体积加起来不到 5 KB（配图另计）。**能自绘的绝不引库**——
> 这是零依赖单文件项目的唯一正解。

## 三、装饰浓度：从「淡薄」到「可见」的具体改动

用户反馈「背景祥云等装饰元素过于淡薄」。改动清单（数值即改动前后）：

| 元素 | 浅色 | 深色 | 说明 |
|---|---|---|---|
| `body::after` 祥云暗纹 | `opacity .15 → .36` | `.14 → .34` | 同时重建 mask：由 220×110 小块（4 朵大云挤一格，观感发「斑点」）改为 **660×330 大周期 + 11 个不同缩放的母题** |
| `.gc-scape` 远/中/近山 | `.13/.16/.20 → .24/.26/.30` | `.16/.22/.30 → .28/.36/.46` | 三档拉开浓淡差，纵深才成立 |
| `.card::after` 卡片云纹 | `.075 → .135`（hover `.13 → .22`） | `.10 → .17` | 卡片也参与装饰，不然背景浓了卡片显飘 |

**新增 v10 装饰层**（全部 `aria-hidden`，不进无障碍树）：

1. `.gc-grain` —— 宣纸颗粒（`feTurbulence` + multiply/screen 双主题适配）
2. `.gcs-haze` —— 云海雾带，`gcHaze 96s` 横移，mask 520×260
3. `.gc-frame` + `.gcf-c1..c4` —— 双金线装裱框 + 四角如意云头（`@media(min-width:981px)` 才出）
4. `.gcsheen` —— 金线流光（`gcSheenSpin 13s`）
5. `.gcs-mid/.gcs-near` 挂 `filter:url(#gcInkEdge)` —— 墨边晕开

**验证方式**（不靠肉眼单点判断）：对基线版与 v10 做**同口径同尺寸截图对照**，
确认四角云头为新增且清晰可见、祥云与远山确实更实。

## 四、事件配图：方案与落地

### 4.1 生图能力调研结论

- **内置 `ImageGen` 工具可用**：文生图 / 图生图，单张约 5–10 credits。
- 因此不需要引第三方生图 skill，也不必引入外部图库（那会踩 §2.1 的许可坑）。
- 配图**由本项目自行生成**：宣纸底、墨分五色、朱砂印、远山云雾，风格与项目同源。

### 4.2 九张画面对应

| 键 | 场景 | 键 | 场景 | 键 | 场景 |
|---|---|---|---|---|---|
| `study` | 学业 | `clinic` | 药庐 | `winter` | 风雪 |
| `market` | 市井 | `home` | 庭院 | `court` | 庙堂 |
| `war` | 沙场 | `journey` | 山水 | `wedding` | 红妆 |

### 4.3 选图逻辑：两层优先

```
sceneArt(ev, key)
  ├─ 若是「职业」类事件且已立身 → 按职业取图（official→court / merchant→market / army→war / doctor→clinic）
  └─ 否则 → 先查 SCENE_ART_KEY[key]（约 20 个语义键，来自 sceneKey 的关键词命中）
              → 再落回 SCENE_ART_CAT[ev.cat]（约 18 个类别兜底）
```

- `sceneKey(ev)` 在事件标题 + 描述里做**关键词命中**，越具体的关键词排越前（「油灯」先于「火」、
  「学堂」先于「书」），并且**只用多字词或语义收敛的字**——单字会误伤（「烧」命中发烧、「信」命中信任）。
- **映射抽检结果**（236 条事件全量扫描，无一落空）：

| 画面 | 命中数 | 样例事件 |
|---|---|---|
| `home` | 63 | 夜啼 / 第一声 / 认生 |
| `market` | 37 | 意外之财 / 投资机会 / 为人担保 |
| `journey` | 37 | 记名 / 山中奇遇 / 贵人相助 |
| `war` | 23 | 上头打压 / 同伴背刺 / 火起 |
| `study` | 19 | 开蒙 / 同窗之谊 / 科考 |
| `clinic` | 19 | 出疹子 / 长辈病重 / 赡养之责 |
| `winter` | 17 | 济人 / 含饴弄孙 / 故人凋零 |
| `court` | 14 | 创业风口 / 升迁之机 / 体制之内 |
| `wedding` | 7 | 说媒 / 婚姻抉择 / 婚姻危机 |

### 4.4 压缩与内联管线

`_artbuild.py`：
1. 裁水印（`WATERMARK_Y=880`）
2. 裁 16:7 横幅（锚点 `ANCHOR=0.42`，偏向画面上部）
3. 缩到 `TARGET_W=540`
4. **自适应质量 WebP**：目标 `17 KB/张`，质量从 64 逐档降到 40，取首个达标值
5. base64 内联；同时输出 3×3 联络表 `_art/sheet.png` 供画质目检

`_inject_art.py`：把 `plates.json` 幂等注入 `<style id="gc-art">`，只生成 CSS 变量与
`.scene.art-*{--art:...}` 映射。

**实测单张体积**（`BUDGET=17 KB`，clinic 因细节多触到质量下限，略超）：

| 键 | KB | 键 | KB | 键 | KB |
|---|---|---|---|---|---|
| study | 16.9 | clinic | 20.4 | winter | 17.1 |
| market | 19.2 | home | 17.2 | court | 16.6 |
| war | 16.9 | journey | 18.7 | wedding | 17.0 |

合计 **160.1 KB**（base64 后约 214 KB），占单文件 **19.5%**。这是在「9 张全覆盖」与「体积可接受」之间的取舍点。

### 4.5 底图为什么挂在伪元素上（一个必须记住的坑）

配图最初挂在 `.scene.has-art` 自身。结果是**深色主题下配图被整体压暗、而 SVG 山体在 `screen`
混合模式下爆白**——因为二者共用同一个元素，只能整体 `filter`。

改法：

- 底图移到 **`.scene.has-art::before`**，`isolation:isolate` 建立独立层叠上下文；
- 深色下只对 `::before` 单独 `filter:brightness(.60) saturate(.74)`，不再牵连 SVG 与卡片淡出；
- 深色下 SVG 改用 `opacity:.44; mix-blend-mode:screen; filter:invert(1) hue-rotate(180deg)`
  —— 浅色填充反相后变暗，在 `screen` 下自动隐去，**只留墨线点睛**。

> 同理要记住：`feDisplacementMap`（墨边晕开）**贴在 `<img>` 上不生效**，必须贴在 SVG 元素上。

## 五、另有两条与视觉并列的本轮改动（简述）

1. **事件默认全部展开**：删掉「再看看」折叠逻辑与 `unfoldOpts`，所有选项一次铺开，
   改用**错峰入场**（`--oi` 序号 → 每项延迟 58ms）承载层次。
   实现细节：动画用 `backwards` 而非 `both` —— 否则动画终态会压住 `:hover/:active` 的 transform。
   reduced-motion 下整段禁用。
2. **粒子特效强化**：`initBgFx` 重写为**四层系统**（墨晕 / 雾气 / 浮尘 / 金屑），
   带精灵预渲染、指针视差、阵风、DPR≤1.5；新增冲击环 `.fxwave` 与金箔翻飞 `.fxleaf`。
