## 0. 先算账：为什么「全改矢量」是唯一走得通的路

第一版是九张 AI 位图，内联后的样式表 **219878 字节**（base64 再涨 33%）。它有个死结：

> 九张图对的是九个**类目**，而事件有三十几种。科举与赶考同一幅、药庐与卧床同一幅、
> 出家与修行同一幅 —— 命中靠猜，猜错就是张冠李戴。

要「贴合对应事件的内容」，位图只有一条路：把画面数乘以三到四。代价是单文件再涨 300KB 以上，
而且位图**不会随事件动**，同一天翻两页看到的是同一张静止图。

矢量反过来：**每个意象都能有自己的画**，还能把「只有这件事才有」的东西画进去 ——
考场是号舍连排、牢里是小窗一道光、厂里是转着的齿轮、灶房是火＋柴＋水缸。
代价是要自己动笔，于是先把画笔做成工具箱（见第 3 节）。

**净结果**：`index.html` **877208 → 687141 字节（-190067，-185.6 KB）**。
减掉的 219878 字节位图，换回来的是 67411 字节的画面代码 + 25556 字节的隧道 + 14554 字节的样式
+ 5925 字节的投胎帖 —— 画面数从 9 涨到 **36 个关键词分镜 + 8 种远景 + 4 类兜底**，体积反而降了近 190KB。

## 1. 撤掉按钮墨涡：为什么这次不留

v11 那一层做得不差（分层、缓动、三个坑都踩过并记在 `v11-墨涡交互方案.md` 里），但它解决的是
**「按钮该怎么响」**；这次要的是 **「这一世该怎么开始」**。

两件事的正确做法是冲突的：

- 墨涡挂在 `pointerdown` / `pointerover` 上，是**高频、无目的**的交互 —— 力度必须压到
  「感觉得到它在转，但说不出在动什么」，而且不能外溢一个像素。
- 时光隧道是**一辈子只有一次**的过场 —— 它就该铺满全屏、有明确方向、有始有终。

把同一套画面语言同时用在两个极端上，结果一定是两头都不对：按钮太吵，隧道太拘谨。
所以 v11 那一层**整层删掉，一个类名都不留**，画布让给隧道。

探针为此加了一条硬断言：**11 个按钮各取样一次悬停与按下，`#vx` 画布上不透明像素必须为 0，
且 `pointerEvents` 保持 `none`** —— 「按钮上不再有任何涡」是被数出来的，不是被肉眼确认的。

> 取样时有个坑：按下再在同一位置抬起＝真的点了一下按钮，会把首页点穿（`#btnStart` 被触发）。
> 所以取样循环必须是「按下 → 移到 (6,6) → 抬起」，探针里另有一条断言守着这件事。

## 2. 时光隧道：一次穿越的四段

`TOTAL = 2.35s`（`prefers-reduced-motion` 时 `.62s`，只留一记柔光）。时间轴按**归一化进度 `u`** 分段，
所有强度都是 `u` 的函数，所以「跳过快进」时每一层都还在自己的位置，不会错位。

| 段落 | `u` 区间 | 画面 | 为什么放在这里 |
|---|---|---|---|
| **起势** | 0 → `.18` | 洞心从一点撑开，速度线开始朝外拉长 | 太短像闪，太长像卡；`.18`≈420ms 是「刚看清要发生什么」的长度 |
| **冲刺** | `.18 → .50` | 旋臂收紧、粒子被吞、暗场随之外扩 | 越飞越快，暗场是它的副产品不是主角 |
| **换屏** | **`.50`** | 在暗场完全铺满的**那一刻**换 DOM | 见下面「为什么换屏要藏在暗场下」 |
| **吞没** | `.50 → .66` | 白闪、光子环、时间环错峰亮起 | 峰值只给 16% 的长度 —— 峰值一长就腻 |
| **退潮** | `.66 → 1` | 一切不透明度乘 `1-u^1.12` 退掉，本体结束 | 出口必须是**淡出**，硬切会像视频断了 |
| **余烬** | 本体之后 | 金屑继续下落、旋转、逐个熄灭 | 落在 2400→4700ms 这一段，是「落定」的尾音 |

实测：换屏 1279ms、本体末 2643ms、余烬末 3235ms、**全清 4112ms 且 `0px / max 0`**。

### 2.1 为什么必须走独立画布

这一条 v11 已经踩过一遍，v12 直接继承：**选项按钮在 `click` 的同一个 tick 里就被整块重建**，
挂在 DOM 上的动画根本播不完。隧道更极端 —— 它要横跨「投胎帖退场 → 人生页挂载」这次换屏，
只有独立画布能把这一下画完整。

```
z-index：.app 1 · .sidebar 45 · .compliance 50 · .mask 60 · #birthCard 66 · #vx 68
```

帖在 66、画布在 68，所以「按下踏入此世」之后隧道**立刻盖过帖**，不需要等帖的退场动画播完。

### 2.2 为什么换屏要藏在暗场下

暗场（`T.fog`）不是装饰，是**换屏的遮罩**。DOM 换屏发生在 `U_SWAP = .50`，而暗场在此之前
就已经铺到接近全不透明 —— 于是「旧屏消失、新屏出现」这一瞬间没有一帧露白。

探针量到的是 **1279ms / 全长 2350ms**，即 `u ≈ 0.54`，比 `.50` 略晚一点点（帧对齐所致），
断言窗口取 `[900, 1700]`。

### 2.3 三处必须写死的地方

1. **白闪只在 `T.on` 为真时点燃**。
   原来写成 `if(u >= U_PEAK && T.flash <= 0)` —— 收尾之后 `u` 恒为 1、永远 `>= U_PEAK`，
   于是每帧重新点一次白闪，**画布再也熄不掉**（实测收尾 `endPx = 172800 / maxA = 255`）。
   改成 `if(T.on && u >= U_PEAK && …)` 才对。
2. **粒子必须在主循环里推进与回收**。
   `stepPart()` 曾经从未被调用：画面看着正常（元素用固定半径画），但粒子**永远不死**，
   于是 `idle()` 永不为真、rAF 常驻空转。补上推进循环后「整层彻底熄灭、rAF 归零」才成立。
3. **`dt` 钳在 `.05`**（宁慢不跳帧）。这条决定了**不能用墙钟去断言时长**：
   无头软件渲染下一帧若耗 183ms，动画钟只走 50ms，2.35 秒的动画墙钟能拖到 2.6 秒。
   所以隧道对外留了一个只读把手 `window.__vxT`，探针读的是**动画自己的时钟**
   （`T.t / T.dur / T.wall / T.lagMax`），墙钟只用来抓「真卡死」。

## 3. 投胎帖：进入之前的最后一屏

`#birthCard`（`z-index: 66`）是一张**全屏绢本**，压在暗场上面 —— 深色主题下它也是浅色的：
这个时刻唯一该亮的东西就是这张帖。

### 3.1 为什么是独立一屏，而不是横幅

原来有个「出生横幅」挂在人生页顶上（`birthHtml`）。问题有三个：

- 它和第一条事件**同时出现**，等于开局信息被事件内容抢了注意力；
- 它挤在页面流里，家境描述只能写一行，讲不清；
- 最关键：**它是「已经开始了」之后才说的**。而用户的诉求是「正式进入之前」。

走廊顺序因此改成：**投胎帖（先说清） → 按下踏入此世 → 时光隧道 → 人生页**。

### 3.2 帖上有什么

| 区块 | 内容 | 来源 |
|---|---|---|
| 帖首 | 第 N 世（`META.lives + 1`，数字转汉字） | 存档 |
| 生年 | 大字号生年 + `<small>` 干支 | 生辰八字 |
| 时代 | 由生年推出的年代文案（如「二十世纪六十年代」） | `bcEra(y)` |
| 四格 | 性别 · 生肖 · 日主 + 五行 · 强弱 | 命盘 |
| 家境 | 徽记 + 一句话描述 + **属性增减**（逐条标正负） | 开局摇的家境 |
| 志向 | 本世志向与它的追问 | `ambition` |
| 寿元 | 年限 + 「天给的年限，未必用满」 | 命盘 |
| 按钮 | 「踏 入 此 世」 | —— |

**属性增减的正负不能只看数值**：`NEG_ATTRS` 里的属性（业力一类）数值涨是坏事。
所以判据是 `good = (v > 0) === (NEG_ATTRS.indexOf(k) < 0)`，颜色才不会反。
（这一条曾经把「财富 -9」画成绿色、把「业力 +7」画成红色 —— 正是这一类错误只有断言能拦。）

### 3.3 交互：可以退

点暗场空白处即可关掉回首页重新投胎 —— 「提醒」不是强制条款，玩家反悔的成本必须为零。
帖上另有 `bcIn` / `bcOut` 两个 keyframe：进场 460ms、退场 300ms（退得比进得快，
因为退场后面紧跟着隧道，多停一帧都是浪费）。

手机端实测帖 **358×588 / 视口 390×844**：一屏放得下，不裁切（探针断言）。

## 4. 矢量水墨画面

### 4.1 三层构图 + 一层动

```
sc-far  远景区（山脊 / 城郭 / 殿宇 / 夜色）—— 决定这件事发生在什么天地间
sc-mid  中景主体 —— 这件事本身
sc-fg   近景（坡石、草木、案角）—— 压住下缘，制造纵深
sc-mot  动（雪落 / 烟起 / 水波 / 旗猎）—— SVG 原生 <animate>，不占 JS 线程
```

微动全走 SVG 原生动画，**不进主线程**：36 个分镜总共 **236 处微动**（雪、烟、波、火苗、
灯摆、光呼吸、云雾横移），一帧 JS 都不用跑。`prefers-reduced-motion` 下整组 `.sc-mot` 收起 ——
SMIL 不受 CSS 管，只能整组隐藏；画面本身是完整的，只是不动。

### 4.2 配色：一条规则画到底，深浅共用一幅画

所有颜色都是 CSS 类 + `--sc-*` 变量，没有一处内联 `fill`。好处有三个：

1. 样式解析一次，几千个元素共用，比内联属性字符串便宜；
2. **深色下换的是「夜里的墨」**（纸变暗、墨变浅），不是把白天那幅压暗凑合；
3. 类名即语义（`sc-water-l` = 水波纹线），回头改配色不用回 JS 里翻。

深浅两套各约 46 个变量，深色只覆盖变量、不动任何类规则。

### 4.3 `defs` 里只有三类东西

其余颜色全是纯色，纯色能跟主题走；只有这三种非渐变/图案不可：

| 类别 | 张数 | 为什么必须是渐变/图案 |
|---|---|---|
| 天光 | 昼 1 + 夜 1 | 径向渐变，单色替代不了 |
| 纸纹 | 绢丝 2 + 纸筋 2 | 斜纹与疏点，靠 pattern 铺满全幅 |
| 远山 | 昼 3 + 夜 3 | **纯色叠三层就是一块灰板子**，把整幅画压死 |
| 罩染 | 昼 1 + 夜 1 | 远景画完整体刷的一道薄墨，把远近咬合在一起 |

**远山为什么必须渐变**：国画里山脚从来不是实的 —— 一笔淡下去，交给云气和纸自己化开。
用 `objectBoundingBox` 的纵向渐变（上缘浓 `.62` → 中段 `.30` → 下缘 `.02`），
每座山各按自己的包围盒渐变，于是「上缘浓、下缘淡」这件事**写一次就全对**，不用逐座去调。

**罩染为什么单开一层**：它压在远景之上、中景之下 —— 远景被这一层收进纸里，中景才是画面最实的东西。
没有它，各层就是贴上去的纸片（这是对比 v10 位图版后补的第一件事）。

### 4.4 关键词优先，类目兜底

`sceneKey(ev)` 从事件标题 / 副标题 / 描述里扫关键词，命中就画出**只有这件事才有**的东西：

| 分镜 | 只有这件事才有的东西 |
|---|---|
| 科举 / 赶考 | 号舍连排、棋盘格 |
| 牢狱 | 小窗一道光 |
| 工坊 | 转着的齿轮 |
| 灶房 | 一炉火 + 一捆柴 + 水缸吊壶 |
| 药庐 | 药柜格 + 药碾 |
| 祠庙 | 供桌 + 牌位（带墨边） |
| 渡口 | 船 + 桅 + 水纹 |

代价是落空时要能兜底：`SC_CAT` 把类目映到 4 张兜底画面（`home`/`roomlife`/`warplain`/`elder`），
`SC_BG` 另有 8 种远景（平远 / 高远 / 旷野 / 水岸 / 城郭 / 殿宇 / 室内 / 夜色）。

**随机性用事件自身做种子**：标题 + 类目 + 年岁走 FNV-1a，再喂 xorshift。
所以同一件事每次重绘一模一样，不同的事苔点、皴笔、云位各不相同。
用 `Math.random` 会让纸纹每换一页都在跳，像坏了。

### 4.5 这次踩的四个坑

| 坑 | 现象 | 根因 | 修法 |
|---|---|---|---|
| **`fill` 继承灌进线里** | 线变成一坨墨团 | 三层构图是 `<g class="sc-mid">` 这类容器，而容器上挂着**同名**的填充色类；SVG 的 `fill` 会继承 | 所有线类统一显式 `fill:none`（一条规则）+ 探针断言「墨线的 computed fill 必须是 `none`」 |
| **`scC()` 把两个数塞进 `cx`** | 2364 条 console error，全部圆形元素堆到左侧 | 写成 `cx="scPt(x,y)"` → `cx="420.9,48.1"`，浏览器报 `Expected length` 并回落 | 拆成 `cx` / `cy` 两个属性 |
| **`court` / `prison` 完全静止** | 「每个分镜至少一处微动」失败 | 这两幕全是色面 + 画面字，一条会动的线都没有 | 新增 `scPulse()`：给光晕与窗光加透明度呼吸；`home`/`elder` 的静态云雾加 `scDrift()` |
| **安全框被当成画幅用** | 主体集体偏左、右边更空 | 把 `SC_SX0/SC_SX1` 从 106/374 改成 74/406（以为「放宽安全区＝填满画幅」）。但这两个数同时是**36 幅画的构图原点**，改它等于把所有以 `SC_SX0 + k` 定位的主体一起左移 32 单位 | 还原为 106/374，并把这条写进注释；判据改成「主体**居中**（中心 240±50）且宽 ≥130」，而不是「撑满」 |

**第 4 个坑值得单独说一句**：`SC_SX0/SC_SX1` 只用来放主体，**溢出的东西**（远山、云气、雪、
水纹、落款）才允许跑出构图框 —— 它们只要落在实测的裁切安全带内就不会被裁：

> 桌面 506×152，`slice` 后可见 `x∈[13,467]`；手机 364×152 时可见 `x∈[58,422]`。

### 4.6 一个探针口径的教训

「画面逐段加码」这条断言最初量的是 `#vx` 画布的 `alpha ≥ 150` 像素数，取样点在起势 / 冲刺 / 峰值。
它失败了，但**不是画面有问题**：暗场本身到 ~900ms 不透明度就超过 150，是一层全屏遮罩，
把洞心的增长整个盖住 —— 再往后测什么都是「满屏」。

修法是把取样点挪到**暗场铺满之前**（200 / 500 / 800ms 三点比增长：4287 → 9287 → 28090 px），
并另加一条「暗场随冲刺铺满」。**读数饱和不是画面不对，是量错了东西。**

同类的还有一条：`画面 paint server` 最初拿「当前这一屏」来验远山渐变，而走到室内那几幕
（`bg:'room'`）压根没有远山 —— 于是把「这件东西本来就不存在」误报成「引用解析失败」。

## 6. 调参入口

| 想改什么 | 去哪里 |
